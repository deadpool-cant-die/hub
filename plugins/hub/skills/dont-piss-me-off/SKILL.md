# 싫어하는 것 점검 (hub:dont-piss-me-off)

> 같은 폴더에 `reference.local.md`가 있으면 먼저 읽는다(회사·이 컴퓨터 전용: 레포·도구 경로·사람·채팅 번호). 공개 사본엔 없다.
> `HUB_SCRIPTS` = 이 플러그인의 `scripts/`(이 스킬 폴더 기준 `../../scripts`).

공통: 답은 짧게, 쉬운 한국어, 맨 앞에 `[HUB]`(레포 하나 얘기면 `[레포이름]`). **실제로 확인한 사실만** 쓴다(이슈 트래커, git, gh, orca, 메모리, TODO.md). 확인 못 한 건 "확인 못 함"이라고 적는다.

## 1. 규칙 읽기
공용 메모리 `feedback-*.md`를 전부 읽고(제목·How to apply), 한 줄씩 점검표로 만든다. 자주 걸리는 것:
- 보여 달라면 바로 띄우기(`hub:show-me`) — 설명만 하고 안 띄우기 금지
- 디자인은 만든 즉시 디자인 서버에 올리고 위치 적기
- 말 돌리지 말고 짧게, 결론 먼저
- 범위를 늘리지도 줄이지도 않기(질문을 지시로 보고 줄이기 금지)
- 확인 안 한 것을 "됐다"고 하지 않기
- 관계없는 질문·이미 미룬 것 다시 묻기 금지
- 결재자(윗사람)께 보내는 글 말투 지키기
- 화면 포커스 옮기지 않기, 세션 안 `/model` 금지

## 2. 어긴 곳 찾기
- 이 세션의 최근 답 몇 개, `orca agent read <orca_session_id> --limit 20`으로 최근 보고한 봇·worker들, 오늘 보낸 메시지 초안.
- 규칙마다 "어김 / 괜찮음 / 볼 수 없음".

## 3. 처리
- 바로 고칠 수 있는 것(내가 쓴 문서 말투, 빠진 위치 표기, 안 띄운 결과물)은 고치고 "고침: …"으로 적는다.
- 남의 봇 일이면 그 봇에 `orca orchestration send --to bot:<이름> --type status …`로 한 줄 지적(보고처 경유).
- 답:
```
[HUB] 점검
고침: …
어김(남은 것): <규칙> — <어디서> — <어떻게 고칠지>
괜찮음: N개
```
