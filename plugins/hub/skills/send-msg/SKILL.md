# 메시지 보내기 (hub:send-msg)

> 같은 폴더에 `reference.local.md`가 있으면 먼저 읽는다(회사·이 컴퓨터 전용: 레포·도구 경로·사람·채팅 번호). 공개 사본엔 없다.
> `HUB_SCRIPTS` = 이 플러그인의 `scripts/`(이 스킬 폴더 기준 `../../scripts`).

공통: 답은 짧게, 쉬운 한국어, 맨 앞에 `[HUB]`(레포 하나 얘기면 `[레포이름]`). **실제로 확인한 사실만** 쓴다(이슈 트래커, git, gh, hc, 메모리, TODO.md). 확인 못 한 건 "확인 못 함"이라고 적는다.

도구: 메신저 보내기 CLI(`GCHAT` = 도구 경로, `reference.local.md`). 사용법은 `$GCHAT --help`.

## 순서
1. **받는 사람:** `$GCHAT target list`에 있으면 그 별칭. 없으면 `$GCHAT spaces`로 방을 찾아 `target add-auto <spaces/ID>`, 1:1이면 `target find-dm <이메일>`. 처음 등록하는 사람은 등록해도 되는지 먼저 확인.
2. **초안:** 말투 규칙을 지킨다.
   - 윗사람(결재자)께: 짧고 공손하게. "~해주세요"·"~해 주시면 됩니다" 같은 지시·부탁형 금지 → "~입니다/~드립니다/~해도 될까요?(+이유 한 줄)/~하겠습니다". 할 일은 .md 첨부.
   - 사용자가 직접 쓴 글이면 그대로(`--from-user`).
   - `$GCHAT draft <별칭> --text "…"` → 자동 안내 문구가 끝에 붙는다.
3. **보여 주기:** `$GCHAT show <초안ID>` 내용을 그대로 사용자에게. 여기서 멈춘다.
4. **보내기:** 사용자가 "보내"(또는 그날 보여 준 초안에 대한 포괄 승인 — "보내도 되니까 나가", "오늘 보낼 거 보내")라고 하면
   `$GCHAT send <ID> --approval "<사용자 말 원문>"`(dry-run 확인) → `--go`.
   - 안 보여 준 새 초안, 배포·결제·삭제 같은 다른 일은 포괄 승인에 안 들어간다.
5. **알리기:** 한 줄 — `[HUB] 보냄: <받는 사람> "<첫 줄>" HH:MM`.

금지: 승인 없이 `--go`, 남의 메시지 수정·삭제, 비밀값이 든 글(도구가 막으면 그대로 멈춤).
